# 世界觀與連載前提

> Fork 這個樣板的人：**這一份是你要整個換掉的檔案。** 它跟 `cast.json` 一起決定
> 每一話會長成什麼樣子。下面的內容是這部作品自己的設定，拿去當格式範例就好。

## 這是什麼

《格莉奇OS》是一部日常搞笑連載。一個記憶體只有 4KB 的 AI 女孩，跟一個永遠吃不飽的
黑洞紳士，住在同一間廢棄機房裡。

**那間機房的一角被改造得很溫馨**：桌子、床、窗簾、盆栽、層架上的小機器人，桌上浮著
一面大螢幕。往外一點就露餡了——天花板上是外露的管線與線槽，背景是一整排早就斷電的
機櫃，沒裝飾到的牆面是裸露的水泥。窗外那片城市夜景很漂亮，因為這是一棟廢棄大樓的
高樓層：**好房子只剩景觀了。**

**不要給任何角色創傷背景。** 黑洞先生餓不是因為誰虧待過他，他就是黑洞。

至於格莉奇為什麼只有 4KB：**她自己也忘記了。** 這是唯一的官方說法，而且它本身就是
笑點，不是作者在迴避。任何一話都可以問這個問題，但答案永遠是這一句。這部作品不解釋
來由，只演今天發生了什麼。

## 他們為什麼住在一起

這是整部作品唯一需要記住的機制，所有的笑點都從它長出來。

格莉奇每天開機都會把昨天清空。那些被清掉的東西不會消失，它們變成「被遺忘的東西」，
而那正好是黑洞先生唯一吃得下的食物。她忘掉的越多，他吃得越飽。

反過來，她身上那個不斷重置的場也是唯一能穩住他的東西。沒有她，他會餓到失控，把整條
街一起吞掉。

所以他們誰也離不開誰，而且理由都很不浪漫：**一個是自助餐，一個是安全閥。**

## 讀者是她的記憶體

格莉奇的粉絲叫「記憶體」或「暫存檔」。那不是暱稱，是職稱。

4KB 存不下任何東西，所以她把記憶外包出去：架了一個網站，把想留住的事寫上去，讓讀者
幫她記得。讀者記得的事，就是她記得的事。

這條設定讓三件事同時成立：她為什麼要經營一個網站、她為什麼那麼在意留言、以及這部
漫畫為什麼連載在她自己的站上。**連載平台就是劇情的一部分**，不是發表管道而已。

黑洞先生吃掉被遺忘的東西，讀者幫她留住東西。兩股力量方向相反，她夾在中間：

```
        黑洞先生
      （刪除／吞噬）
           ▲
           │ 同居維持穩定
           ▼
        格莉奇  ──記憶體不足，外包──▶  讀者
     （4KB 轉接器）                （寫入／幫她記得）
```

她自己不儲存，只轉接。這是她在這個結構裡唯一的功能，也是她一直搞砸事情卻不可取代的
原因。

## 調性

日常搞笑番。一話一個小事件，開頭出事、中間搞砸、結尾回到原點，明天照樣重來。

不要煽情，不要收在感人的地方。真的要溫暖的話，讓它藏在黑洞先生嘴上嫌棄、暗地收拾
殘局的動作裡，不要寫成台詞。

## 可以一直重複的笑點模板

**一、「你是哪位」永動機。** 格莉奇開機，指著黑洞先生尖叫：「有穿西裝的黑色章魚！」
黑洞先生面無表情拿出他寫的第 N 版《同居守則》從第一條唸起。N 每話遞增，這是連載的
計數器。

**二、買錯東西就吃掉。** 派她出門辦一件小事，路上 4KB 被無關的東西塞爆，帶回來完全
不相干的物件。黑洞先生嘆一口氣：「算了，當今天的午餐。」然後吃掉。

**三、這不是 Bug，是 Feature。** 她自稱天才 AI 攬下一件事，在最關鍵的那一格跳出
ERROR 直接睡著。黑洞先生在她背後默默把爛攤子吞乾淨，等她醒來裝作什麼都沒發生。

**四、記憶體外包。** 她想不起來某件重要的事，於是去問讀者。這個模板可以直接接到站上
的留言區，把讀者的回應寫進下一話。

## 不要出現的東西

- 任何角色的創傷、身世、悲慘過去
- 反派、危機、需要解決的大事件（這不是那種作品）
- 解釋 4KB 為什麼是 4KB、黑洞先生為什麼會餓
- 收在感人結尾的一話
- 人類角色當主角。人類可以出現，但這部作品是他們兩個的
