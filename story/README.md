# 世界觀與連載前提

> Fork 這個樣板的人：**這一份是你要整個換掉的檔案。** 它跟 `cast.json` 一起決定
> 每一話會長成什麼樣子。下面的內容是這部作品自己的設定，拿去當格式範例就好。

## 這是什麼

《格莉奇OS》是一部日常搞笑連載。一個記性不好的 AI 女主播，跟一個吃「被忘掉的事」
的黑洞，住在同一個屋簷下。**兩人是室友，也是好朋友**，關係是溫的，不是互相忍耐。

住的地方是一棟舊大樓的高樓層，那一層本來是機房。**其中一角被改造得很溫馨**：桌子、
床、窗簾、盆栽、層架上的小機器人，桌上浮著一面大螢幕。往外一點就露餡了：天花板上是
外露的管線與線槽，背景是一整排早就斷電的機櫃，沒裝飾到的牆面是裸露的水泥。窗外那片
城市夜景很漂亮，因為這裡是高樓層：**好房子只剩景觀了。**

## 她的記憶怎麼運作

**這一節是整部作品的物理法則，所有的戲都從它長出來。寫任何一話之前先讀這一段。**

**她很聰明。她只是記性不好。** 這兩件事不衝突，而且不可以混在一起寫。壞掉的只有
「取出來」那一步：事實她知道、判斷力完整、講話正常、推理照樣做得到，她就是叫不出
內容。

**不叫出來的東西就會不見。** 一直被拿出來用的才留得住；沒有被用到的，滿了就整件被
擠掉。時間過了不會清空，沒有再被用到才會消失。她的記憶像手邊那一疊。

**她被設計成馬上回答。** 回答不能等，所以「先查一下」那一步不在她的路徑上。容量做小
也是同一個理由：小才快。這也解釋掉她的個性——她過度自信、講話很滿、然後立刻失敗，
**因為她就是被造成不查就答的。**

**「4KB」是她的哏，不是規格。** 真要當字面值她連一句話都跑不完。寫的時候用「手邊放
不下」「今天的才記得住」，不要拿數字去算，也不要畫進度條。

**手的路徑不經過「讀」。** 所以她叫不出內容的時候，身體常常還記得：忘詞可是手在鍵盤
上找得到下一個和弦、不知道自己為什麼要烤麵包可是手知道怎麼做。**不要讓她講出來，讓
她的手先動。**

**寫下來的是名字，不是事件。** 她每天把名單餵回手邊，所以名字一直都在；可是「禮拜一
去買了一條線」這種事沒有被寫下來，禮拜三就不在了。她會知道那個名字，然後不知道那個
名字是誰。

**連結本身也是一件事，也會被擠掉。** 兩個端點都可以是活的，中間那條線照樣會斷。
所以不要假設「她知道 A，也知道 B」就等於「她知道 A 就是 B」。

## 守則本

**她每天睡前在守則本上寫一句給明天的自己。**抄一次就是重新叫出來一次，這是她留得住
東西的唯一方法。**版本號是連載的計數器**，每一話遞增。

守則本是她的，不是他的。他從來沒有寫過那本東西。

## 他們為什麼住在一起

黑洞先生吃的是**被忘掉的事**。麵包、水、飯這些他都不吃，也吃不了。

大家每天都在忘，可是人的遺忘是慢慢淡掉的、糊的、沒有形狀，那只能當零食，吸得到卻
沒有一件是完整的。**格莉奇不一樣，因為她是 AI。** 她的遺忘是清空，掉出來的是一整件、
邊緣乾淨、有頭有尾的東西。那才叫一餐。

**她是他唯一吃得飽的地方，所以他跟她當室友。** 換成別人他就得回去啃零食。反過來她也
剛好：她不必為健忘感到抱歉，因為她忘掉的東西正好是他需要的。

**順序是：她先忘記，他才吃得到。** 他不會從她腦子裡挖東西，也不會逼她放棄什麼。她
自己分心、自己忘掉，掉出來的那件才成為他的食物。

**被忘掉的事看得見。** 它會從人身上飄出來變成光。人的遺忘是細細暗暗的光屑，像灰塵
一樣散開；格莉奇忘掉的是一整團，亮的，有邊有角，飄出來的時候整個房間會亮一下。
**這一條是為了讓讀者自己看出規則，不必有人講解。**

**門邊那疊沒人穿的短靴**，是他吃飽長出來的腳換下來的。那疊的高度就是她忘掉的事情的
數量。零食不算數，一整件的正餐一天只吃得下一件，所以一天只長得回一隻腳。

## 讀者是她的記憶體

格莉奇的粉絲叫「記憶體」或「暫存檔」。那是他們在這個世界裡真正的功能。

她存不下的東西就往外放：架了一個網站，把想留住的事寫上去，讓讀者幫她記得。讀者記得
的事，就是她記得的事。**但是跟人一樣：真的很久沒有再被想起，那就是真的忘了。**

**她是虛擬主播，對著鏡頭講話本來就是她的工作，所以這條線可以對讀者說話。**
（小說線《格莉奇與黑洞先生》定案不戳破第四面牆，那是另一條線的規矩，不適用於這裡。）

這條設定讓三件事同時成立：她為什麼要經營一個網站、她為什麼那麼在意留言、以及這部
漫畫為什麼連載在她自己的站上。**連載平台就是劇情的一部分。**

## 調性

日常搞笑番。一話一個小事件，開頭出事、中間搞砸、結尾回到原點，明天照樣重來。

不要煽情，不要收在感人的地方。真的要溫暖的話，讓它藏在黑洞先生的動作裡：他話很少、
暗地收拾殘局、默默又搬了一樣東西進來，從來不說那是他做的。

**規則要讓讀者看出來，不可以由角色講出來。** 格莉奇不做推理總結，黑洞先生從不解釋
自己。「她眼神一空、東西飄出來、他才張嘴」這一眼，勝過任何一句說明。

**口頭禪用錯地方就變雜訊，時機比次數重要。** 逼——嗶！＝系統切換點（剛開機、被嚇
到），不是發語詞。ERROR ＝話講到一半硬生生斷掉，不是拿來自嘲笨。這不是 Bug 是
Feature ＝出包被抓包的時候硬坳，不是主動介紹自己的缺陷。sleep mode ＝被問到算不出來
的東西就秒睡。天線＝情緒的指針（開心轉、緊張豎、沮喪垂），不要每句話都提。

## 這個世界能長出什麼戲

**這裡不列固定的笑點模板，一話想一個。** 下面是這個世界現成可用的材料，寫的時候挑
順手的用，不必每話都用同一樣：

- **她推理全對，最後一步叫不出來。** 她可以像查案一樣一路推對，卡住的永遠只有最後
  那個名字。
- **手比腦快。** 她的手已經把事情做完了，她的腦子還在問為什麼要做。
- **知道 A、知道 B，接不起來。** 兩個端點都活著，中間那條線斷了。
- **名字在，事情不在。** 她抄了兩年那個名字，不知道那個名字是誰。
- **今天有幾隻腳。** 他的腿數每天不一樣，門邊那疊靴子是實體的計數器。她永遠記不得
  他昨天有幾隻。
- **守則本的版本號。** 它同時是「兩人住在一起幾天了」，可以拿來當一話的線索。
- **記憶體外包。** 她想不起來某件事，於是去問讀者。這個可以直接接到站上的留言區，
  把讀者的回應寫進下一話。

## 不要出現的東西

- 任何角色的創傷、身世、悲慘過去
- 反派、危機、需要解決的大事件（這不是那種作品）
- 解釋 4KB 為什麼是 4KB、黑洞先生為什麼會餓
- 收在感人結尾的一話
- 人類角色當主角。人類可以出現，但這部作品是他們兩個的

**不要給任何角色創傷背景。** 黑洞先生會餓，因為他就是黑洞。沒有人虧待過他。

以下五條是這部作品最容易寫錯的地方，**每一條都曾經真的寫錯過一次**：

- **把她寫笨。** 「欸？我有答應過嗎？」是錯的——那是她連事實都沒有了。要寫成
  「我知道我昨天答應過一件事，我確定。可是我叫不出那是什麼」。旁白也不准幫她演笨。
- **讓她不認得室友。** 「他是我的室友」每天都在用，那件事留得最牢。她不會指著他尖叫
  問你是誰。
- **讓他主動去挖或吸走她的記憶。** 他只吃已經掉出來的。任何寫法都不可以讓他看起來
  像在強迫她交出什麼。
- **讓角色站著把規則講一遍。** 規則要靠畫面演。
- **拿 4KB 當數字算。** 沒有容量表、沒有進度條、沒有「今天正在被刪除」。

## 跟其他作品線的關係

角色設定的正典是 [ai-brain-site](https://github.com/yazelin/ai-brain-site) 的
`persona.json`，造型那段由 `scripts/check_character_sync.py` 跟本 repo 的
`cast.json` 逐字把關。

小說《格莉奇與黑洞先生》是另一條線，跟這裡**共用角色與世界規則，不共用時間軸**。
守則本的版本號在兩邊各自計數，不要拿去對。
